# LOKO HUB 1.4 — RELEASE REPORT

**Дата:** 2026-11-14
**Базовая версия:** 1.3.0 → **1.4.0**

---

## 1. Резюме

Прототип 1.3 превращён в функционально работающую систему по этапам 0–5
мастер-ТЗ. Все пять экранов работают на реальных серверных данных; Supabase
подключён; матч-центр имеет централизованный кэш и fallback; состав — единый
источник; LOKO MEDIA — реальный пайплайн (ручное добавление + готовый RSS-сбор);
голосования — через backend с защитой от повторного голосования.

## 2. Этап 0 — техническая гигиена

**Сделано:**
- README полностью переписан под фактическое состояние (раньше описывал
  несуществующие функции).
- Локальный запуск переведён на `netlify dev`; статический сервер сохранён
  как `npm run dev:static` с явным предупреждением об ограничениях.
- Удалён протухший хотлинк `images.openai.com` — фон болельщиков теперь
  фирменный CSS-паттерн в цветах клуба.
- Логотипу добавлен локальный fallback (значок «Л»), обработчик — вне HTML
  (для CSP без inline-скриптов).
- `.env.example` дополнен `VOTE_FINGERPRINT_SALT`.
- Рабочие копии аудита исключены из Git (`.gitignore`).

**Не сделано (блокировка среды):** проверка git-истории на секреты — на
машине не работает запуск процессов из оболочки. Действие владельца:
выполнить `git log -p --all | findstr /R "api_key secret token"` (или
аналог) в основном репозитории.

## 3. Этап 1 — Supabase и матч-центр

**Сделано:**
- `lib/supabase.js` — ленивые клиенты (admin/anon), безопасное отсутствие env.
- `lib/cache.js` — централизованный кэш в таблице `cache` с TTL.
- `lib/football-service.js` — ядро: retry/backoff (3 попытки, 429/5xx/таймаут),
  нормализация, TTL 60 с в LIVE и 30 мин в остальное время.
- `football.js` — тонкий handler с валидацией входа.
- `refresh-football.js` — планировщик (netlify.toml, */30 * * * *).
- Матчи сохраняются в `matches` (upsert по `provider_match_id`), история
  задач — в `ingestion_runs`.
- **Fallback:** при сбое Highlightly отдаётся последний кэш с `stale: true`,
  меткой `fetchedAt` и предупреждением; клиент показывает «Обновлено: …»
  и жёлтую пометку об устаревших данных.
- Нет кэша и нет Highlightly — честная ошибка 5xx, ничего не выдумывается.

## 4. Этап 2 — единый источник состава

**Сделано:**
- Миграция `002_players_unique.sql` — уникальный индекс (team_id, name).
- `scripts/migrate-squad.js` — загрузка проверенного JSON в `teams`/`players`,
  идемпотентная, с логом в `ingestion_runs`.
- `squad.js` — выдача состава из Supabase (кэш 6 ч, fallback на кэш).
- Удалён захардкоженный `playersData` (устаревшие номера Баринов №6 и др.).
- Новый экран игрока: только подтверждённые поля; фото — только если есть
  проверенный URL; остальное честное «—».
- Клиент: состав с сервера, fallback на локальный JSON при недоступности API.

## 5. Этап 3 — LOKO MEDIA

**Сделано:**
- `content.js` — лента из `content_items` (фильтр по категории, кэш 10 мин,
  fallback на кэш).
- `lib/rss.js` — безопасный парсер RSS 2.0/Atom без зависимостей.
- `refresh-content.js` — планировщик сбора (*/30 * * * *): нормализация,
  дедупликация по (source_id, external_id), логи, изоляция ошибок источников.
- `scripts/seed-sources.js` — реестр первой волны (EzheGram, Иванов,
  Art Vandal on Tour, LOKO Раздора) **неактивными** до согласования прав.
- `scripts/add-content.js` — безопасное ручное добавление карточки-ссылки.
- Клиент: LOKO MEDIA рендерится из API, карточки ведут на оригиналы,
  демо-контент удалён, честное пустое состояние.

## 6. Этап 4 — сообщество

**Сделано:**
- `polls.js` — активные опросы с серверным подсчётом голосов (кэш 30 с).
- `vote.js` — только POST: валидация опроса/окна/варианта на сервере,
  fingerprint = sha256(IP+UA+salt), UNIQUE против повторного голоса,
  rate-limit по IP (10/мин), код 409 при повторе.
- `scripts/create-poll.js` / `close-poll.js` — административный механизм.
- Клиент: экран «Болельщики» и «Опрос дня» на Главной — реальные опросы,
  результаты с процентами после голосования, повторный голос заблокирован.

## 7. Этап 5 — тесты, безопасность, мониторинг

**Сделано:**
- Тесты `node:test` (5 файлов): хелперы матч-центра, RSS-парсер, логика
  опросов/голосования, сканер секретов в клиентском и серверном коде,

- Security-заголовки в `netlify.toml` (CSP, X-Frame-Options, nosniff и др.);

- Мониторинг фоновых задач — таблица `ingestion_runs` (football, content,

- Корректные HTTP-статусы: 400/405/409/413/429/5xx.

**Не выполнено (блокировка среды):** фактический прогон `npm test`,
`netlify dev` и деплой — на этой машине не запускаются процессы

## 9. Что требуется от владельца

1. **Supabase:** применить `supabase/migrations/001_initial_schema.sql` и
   `002_players_unique.sql` (SQL Editor), взять URL/anon/service ключи.
2. **Netlify:** Site settings → Environment variables: `HIGHLIGHTLY_API_KEY`,
   `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_KEY`,
   `VOTE_FINGERPRINT_SALT` (случайная строка, напр. `openssl rand -hex 32`).
3. **Локально:** `npm install`, `netlify login`, `npm run dev`,
   `npm test`, `node scripts/migrate-squad.js`, `node scripts/seed-sources.js`.
4. **Опрос:** `node scripts/create-poll.js --question "..." --options "А,Б,В" --days 3`.
5. **Медиаисточники:** решить, с кем из первой волны есть согласование;
   при наличии — дать RSS-ленту (для Telegram-каналов без API подойдёт
   публичный RSS-мост), активировать источник в `sources`
   (`integration='rss'`, `feed_url`, `is_active=true`) либо добавлять
   материалы вручную через `add-content.js`.
6. **Git:** скопировать изменения в основной репозиторий
   `C:/Users/Иван/Documents/GitHub/Loko-hub`, проверить историю на секреты,
   запушить — деплой произойдёт автоматически.
7. Проверить покрытие РПЛ и нужных полей на фактическом тарифе Highlightly
   до оплаты платного плана.

## 10. Известные ограничения 1.4

- Логотип и фоны стадиона — внешние CDN (postimg, fclm.ru); перенос в
  `assets/` — после решения о правах на изображения.
- Антифрод голосований — fingerprint, не аутентификация; накрутка со сменой
  IP возможна (честно заявлено пользователю в интерфейсе не требуется,
  но и защитой «абсолютной» не считается).
- События/статистика матча — только если тариф Highlightly их отдаёт.
- Rate-limit голосований in-memory (на инстанс функции) — при нескольких
  инстансах лимит умножается; для 1.4 достаточно.
